# Fine-tuning RLDX-1 on `lerobot/pusht`

This guide walks through fine-tuning `RLWRLD/RLDX-1-PT` on the
[`lerobot/pusht`](https://huggingface.co/datasets/lerobot/pusht) dataset.
It serves as the smallest reproducible validation of the `PT → FT` path
before integrating RLDX-1 into a downstream stack.

Push-T is a 2D planar task: push a T-shaped block to a target pose using a
single top-down camera. It has no gripper, no tactile sensing, and no
language annotations, which makes it the simplest possible end-to-end check
that the fine-tune pipeline works.

## TL;DR

```bash
cd RLDX-1

# 1. Download the dataset (v2.1 format)
uv run python download_pusht.py

# 2. Add the required meta files (modality.json is committed; generate stats.json)
uv run python rldx/data/stats.py \
    --dataset-path examples/pusht_lerobot \
    --embodiment-tag GENERAL_EMBODIMENT \
    --modality-config-path rldx/configs/data/pusht_config.py

# 3. Validate the dataset loads through RLDX-1's loader
uv run python validate_pusht_config.py

# 4. Train
bash run_scripts/train/examples/finetune_pusht.sh
```

## Why this is not a one-liner

Two format mismatches between LeRobot and RLDX-1 require attention.

### 1. Dataset format: v3.0 vs v2.1

`lerobot/pusht` on the Hub defaults to **v3.0** (parquet-based metadata),
but RLDX-1's `LeRobotEpisodeLoader` expects **v2.1** (JSONL-based metadata:
`episodes.jsonl`, `tasks.jsonl`). Loading the v3.0 default fails with
`ValueError: Feature type 'List' not found`.

The fix is to download the `v2.1` tag directly — no conversion, no
`lerobot` install needed:

```python
from huggingface_hub import snapshot_download

snapshot_download(
    "lerobot/pusht",
    repo_type="dataset",
    revision="v2.1",          # pin the v2.1 tag
    local_dir="./examples/pusht_lerobot",
)
```

The Hub repo exposes tags `v2.1` and `v3.0`, plus branches `v2.0`, `v1.x`.

### 2. Missing metadata files

RLDX-1's loader requires two files the LeRobot dataset does not ship:

| File | Source |
|---|---|
| `meta/modality.json` | Written by hand (see below). **Required** — the loader errors if missing. |
| `meta/stats.json` | Generated by `rldx/data/stats.py`. v2.1 ships `episodes_stats.jsonl` instead. |

#### `meta/modality.json`

Describes how to slice the flat `observation.state` / `action` vectors into
named joint groups, and how to remap video columns to logical keys:

```json
{
    "state":  { "agent_pos": { "start": 0, "end": 2 } },
    "action": { "agent_pos": { "start": 0, "end": 2 } },
    "video":  { "image": { "original_key": "observation.image" } }
}
```

The joint-group names (`agent_pos`, `image`) must match the
`modality_keys` declared in the Python modality config.

#### `meta/stats.json`

```bash
uv run python rldx/data/stats.py \
    --dataset-path examples/pusht_lerobot \
    --embodiment-tag GENERAL_EMBODIMENT \
    --modality-config-path rldx/configs/data/pusht_config.py
```

> **Why `--modality-config-path`** — the Push-T config is registered
> dynamically via `register_modality_config` (like `simpler_widowx`), so it is
> not present in the static `MODALITY_CONFIGS` dict that `stats.py` imports.
> Without this flag the relative-stats step raises
> `KeyError: 'general_embodiment'`. Passing the config path loads it the same
> way the training launcher does. Push-T uses only `ABSOLUTE` actions, so no
> relative stats are written — but the run exits cleanly.

## Dataset facts

From `meta/info.json` (v2.1):

| Field | Value |
|---|---|
| fps | 10 |
| episodes | 206 (1 chunk) |
| `observation.image` | `[96, 96, 3]` video, single top-down camera |
| `observation.state` | `[2]` float32 — agent `(x, y)` in pixel space `[0, 512]` |
| `action` | `[2]` float32 — **absolute** target position, range `~[12,25] → [511,511]` |

The action is an absolute target position, not a delta. This drives the
action-config choice below.

## Modality config

[`rldx/configs/data/pusht_config.py`](../rldx/configs/data/pusht_config.py)
registers the Push-T config against `GENERAL_EMBODIMENT`:

```python
pusht = {
    "video": ModalityConfig(delta_indices=[0], modality_keys=["image"]),
    "state": ModalityConfig(delta_indices=[0], modality_keys=["agent_pos"]),
    "action": ModalityConfig(
        delta_indices=list(range(0, 16)),
        modality_keys=["agent_pos"],
        action_configs=[
            ActionConfig(
                rep=ActionRepresentation.ABSOLUTE,
                type=ActionType.NON_EEF,
                format=ActionFormat.DEFAULT,
            ),
        ],
    ),
}

register_modality_config(pusht, EmbodimentTag.GENERAL_EMBODIMENT)
```

Two choices matter:

- **`ABSOLUTE`** — the action is a target position, not a delta (confirmed
  by the stats range above).
- **`NON_EEF`** — Push-T's 2D action is an abstract vector, not a 6DOF
  end-effector pose. The `EEF` code path asserts a 9D state (`xyz + rot6d`)
  and would crash on the 2D Push-T state.

## Training

[`run_scripts/train/examples/finetune_pusht.sh`](../run_scripts/train/examples/finetune_pusht.sh)
runs an 8-GPU fine-tune from `RLWRLD/RLDX-1-PT`:

```bash
bash run_scripts/train/examples/finetune_pusht.sh
```

Defaults: `GENERAL_EMBODIMENT`, 5000 steps, global batch size 256, checkpoint
every 500 steps to `ckpt/rldx1/finetuned/pusht/`. Override the base model or
dataset with the `BASE_MODEL_PATH` / `DATA_DIR` environment variables.

Watch for:

- Loss trending down by ~step 1000.
- A checkpoint written under `ckpt/rldx1/finetuned/pusht/`.

If you hit CUDA OOM, lower `--global-batch-size` to 128 or 64. Drop
`--use-wandb` to disable logging.
